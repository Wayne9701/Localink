# Security and credential boundary

Report a suspected vulnerability privately to the repository owner or maintainers through an agreed channel. If GitHub offers private vulnerability reporting for this repository, you may use it. Do not include credentials, credential files, sensitive logs, or vulnerability details in a public issue or pull request. No public disclosure address is configured in this repository.

This repository is source and test material. It must not contain a real Tunnel runtime credential, private key, tenant configuration, personal workspace state, or another machine's `~/.localink/` data. Test strings such as `synthetic-service-secret` and `example.invalid` are fixtures. The Tunnel credential and profile are provisioned per Mac outside the checkout; the credential file must satisfy the ownership and mode checks in [the macOS install guide](docs/INSTALL_MACOS.md).

The public MCP surface is bounded to 27 tools. Process is disabled by default; only the local CLI changes that policy. Enabling Process permits host execution, and a workspace working directory does not confine an executable like an OS sandbox. Shared Skills are untrusted content.

External MCP bridging accepts only configured credential-free loopback HTTP or absolute-command local stdio providers. It never turns configuration into an arbitrary remote HTTPS proxy and does not weaken the existing URL, executable, argument, environment, redirect, or secret-like argument checks. Annotation-derived reads, ordinary writes, and destructive/open-world tools become Localink tiers 0, 1, and 2. Missing or ambiguous annotations remain hidden unless a bounded exact-name local override assigns tier 0, 1, or 2; tier 3, patterns, invalid overrides, and unknown matches fail closed or remain isolated. A Tier 2 provider call requires a matching short-lived, single-use confirmation ticket. Provider business logic, authentication, installation, authorization, and any verification receipt remain provider-owned; Localink does not copy, own, or auto-fallback provider identity or credentials and does not auto-retry ambiguous writes.

Before distributing a new commit or artifact, review tracked files and the release payload for credentials and private host details. `npm run check` includes portability checks, but automated scans cannot establish that every string or newly added file is safe to publish.
